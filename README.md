# NuRoots

Private, family-first genealogy app hosted at [nuroots.clearteck.org](https://nuroots.clearteck.org).

The public tree is a sample with fictional people. Changes to the example stay in the browser until refresh. Family accounts are separate and stored in Cloudflare D1. Real family records and editing will come with the private tree.

### v0.2.0-alpha.1 — 2026-11-22

First local pilot with fictional family data. It builds on the public sample tree and invitation-based sign-in.

- Editors can save people and relationships in D1, cite sources, review name changes, and undo a name correction.
- Branches and circles have separate memberships. Stewards review invitations, recipients accept them, and organizers can manage account access.
- A disposable local preview, automated browser checks, and a D1 restore rehearsal make the milestone reproducible.

## Family sign-in

- Family members use an invitation link to set an email and password, then sign in at `/signin`.
- The owner can create single-use viewer or editor links from `/account`. Share links privately with the intended relatives. Links expire in 48 hours. Creating a new link for the same email replaces the previous link.
- Password credentials and sessions are separate from member identities and roles. Additional sign-in methods can reference the same member IDs. Passkeys, authenticator codes, and self-service password recovery are future features.

## Quick local preview

With Node.js 22.12 or newer installed, run `npm ci` and then `npm run preview`. Open the local sign-in URL printed in the terminal. The command creates fictional owner, editor and viewer accounts, prints a temporary password, and seeds a family tree, two branches and a circle. The owner stewards Harlow, the editor stewards Bennett, and the viewer stewards Family Quilters. Stop it with Ctrl+C to discard the session. Restart after changing source code.

## Local development

With Node.js 22.12 or newer, run `npm ci` and `npm run db:init`. The database command applies the base schema and all tracked migrations to local D1 storage under `.wrangler/state`. It can be run again to apply new migrations.

Run `npm test` to exercise accounts, tree editing, branch admissions, access removal, and the disposable preview in the local Workers runtime. The test creates an isolated D1 database, fictional accounts, and a temporary auth secret on each run.

Run `npx playwright-core install chromium` once and `npm run test:browser` to check tree corrections, sources, community admission, and removal in a real browser. Set `NUROOTS_CHROME_PATH` to an installed Chrome executable to use it instead. CI runs the integration suite, recovery rehearsal and browser checks on pushes and pull requests. The browser check includes automated WCAG A and AA checks on selected pages at phone and desktop widths.

For browser development, add an `AUTH_RATE_SECRET` entry to `.dev.vars` with a local-only value generated by `openssl rand -hex 32`. Run `npm run dev` and open `http://localhost:8787`. The checked-in Worker configuration is for local development. Production uses the deployment settings below.

### Try the family tree preview

After `npm run db:init`, run `npm run db:seed` to add a fictional family to local D1. If the local database has no owner account, generate a local invitation and apply its SQL:

```sh
node scripts/owner-invitation.mjs organizer@example.test --local > .wrangler/local-owner.sql
npm exec -- wrangler d1 execute DB --local --file .wrangler/local-owner.sql
```

Open the printed `localhost` join link while the dev server is running, set a password, and sign in. From **Your family account**, choose **Explore the family tree preview**. Try opening Eleanor Bennett, then her parent Rose Harlow, then Rose’s parent Clara Harlow.

From `/tree`, search by name or page through the picker. A person’s page links to their parents, partners, and children. Signed-in members can also read a visible person’s ID and display name at `GET /api/tree/people/:id`.

Owners and editors can make four kinds of changes in the local preview.

- **Add a person** creates a fictional record after the editor confirms the person is deceased.
- **Edit name and view changes** saves a correction, shows recent corrections, and can undo the latest one. A stale form asks the editor to reopen the record.
- **Edit relationships** finds a second person and lets the editor add or remove a parent, child, or partner. The tree checks for duplicates and parent cycles.
- **Review sources** records a source title and where to locate it. Sources are plain text and visible to editors and owners in the preview.

These operations write to D1 and record the actor and change in the audit log. Living records are hidden from browsing, editing and search. Keep all preview flags disabled in production pending the family privacy review.

Run `npm run db:rehearse` to exercise a local upgrade and restore. It creates two temporary D1 databases, migrates fictional records, exports the first database, imports the second, then compares schema, accounts, tree records, change history and foreign keys.

With `ACCOUNT_ADMIN_PREVIEW_ENABLED` enabled, the owner can choose **Manage family account access** to switch between viewer and editor roles or deactivate a family account. Deactivation invalidates every existing session. Reactivation requires a fresh sign-in and preserves the person’s previous memberships. Membership removal on a branch page affects only that branch.

### Try branch and circle membership

After joining as the local owner, run `npm run db:seed:community`. Open **Your branches and circles** from the account page and select **Harlow family**. This fixture explicitly grants the local owner stewardship of the sample branch. Global account roles grant no community access on their own.

To try admissions, create a second fictional family account with the ordinary owner invitation flow. An existing branch member can propose that account’s email from the branch page. A steward approves or denies the request. The recipient sees an approved invitation under **Your branches and circles** and joins by accepting it while signed in. Pending requests and approved invitations each expire after 48 hours. A steward can revoke an approved invitation before acceptance. **Manage members** lets the steward remove a regular member from that community.

The community preview uses `COMMUNITIES_PREVIEW_ENABLED`. Its member-scoped list and detail endpoints are `GET /api/communities` and `GET /api/communities/:id`. The list returns up to 24 memberships and a `next` value to pass as `?after=` for the next page.

## Cloudflare deployment

The `nuroots` Worker serves `src/worker.js` with its sibling modules. Keep its existing custom domain and set the following Worker configuration.

- Compatibility flag `nodejs_compat`.
- D1 binding `DB` pointing to the `nuroots` database.
- Worker secret `AUTH_RATE_SECRET` with at least 32 randomly generated bytes, encoded as hex. Preserve it across deployments.

For a new database, run `schema.sql` first. For both new and existing databases, run `migrations/001_auth.sql` before deploying the auth Worker. The auth migration is additive and safe to reapply. The local previews additionally require tracked migrations 002 through 006, applied once in order. The checked-in configuration enables all three preview flags for local testing.

## First owner setup

Run `node scripts/owner-invitation.mjs OWNER_EMAIL` locally and execute the SQL it prints in the `nuroots` D1 console. Open the private setup link printed by the script and enter the same email. The link allows one owner account to be created and expires 48 hours after the SQL runs. Keep the link and any real family information out of the public repo.
